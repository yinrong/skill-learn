**基于 Route 2.1.1 SPC Nelson 规则分析实验（Round 1–3）**  
**版本：最终版（Round 3 完成后更新）**  
**最后更新：2026-05-03**

---

## 一、什么是"技能内化"（Skill Internalization）？

**技能（Skill）** 是一套结构化的程序性知识——规则、启发式方法、决策树——使智能体能够执行复杂任务。例如：SPC Nelson 规则（过程控制异常检测）、ICD-10 编码准则、安全漏洞模式库、法律合同审查检查表。

**内化（Internalization）** 指模型在推理时**不需要**技能文档出现在上下文窗口中，就能应用该技能。模型通过训练将技能"记忆并整合"到了权重中。

这与以下方式有本质区别：
- **RAG / 上下文技能**：每次推理都附带技能文档（有效，但 token 成本高，且有泄露风险）
- **工具调用**：调用外部系统（需要基础设施）
- **单纯事实记忆**：模型知道规则的内容，但无法可靠地执行

**目标**：无技能文档的推理（ns）达到接近有技能文档推理（ws）的 F1。

### 本项目结果总结（含提取器公平性验证）

| 设置 | 评测条件 | 样本数 | F1 | CPK率 | 说明 |
|------|---------|--------|-----|-------|------|
| Claude Sonnet 4.6 | no-skill，regex 提取 | 200 | 0.110 | 0.025 | 原始测试；regex 提取器为 SFT 格式设计，Claude 英文输出几乎不可提取 |
| **Claude Sonnet 4.6** | **no-skill，JSON 提取²** | **50** | **0.424** | **0.88** | **公平基线（无规则文档）；JSON 解析失败 14%** |
| Claude Sonnet 4.6 | with-skill，JSON 提取² | 50 | 0.348 | 0.62 | 技能文档触发冗长输出，JSON 解析失败 38%，反不如无技能 |
| SFT 14B LoRA（Round 2）| no-skill，regex 提取 | 200 | 0.430 | 1.000 | 训练对齐输出格式，提取率完美 |
| **SFT 14B LoRA（Round 3）** | **no-skill，regex 提取** | **200** | **0.420** | **1.000** | **R3-AB-v2，本项目最优** |

² JSON 评测方法：替换原始"写全文报告"指令为"检查后输出 JSON"，无扩展思考（max_tokens=3000），提取文本末尾最后一个完整 JSON 对象。

**关键结论（修订版）**：控制提取器偏差后，**SFT（0.420）≈ Claude 无技能（0.424）**，两者能力基本持平。原始 0.110 是严重的测量偏差，不反映 Claude 的真实能力。SFT 的核心优势不在规则知识（两者相当），而在**格式一致性**：CPK 提取率 1.000 vs 0.88，输出格式对齐评测标准，可靠性更高。

**"技能文档反而降低 F1"的解释**：有技能文档时，Claude 被驱动输出更详细的分析报告（JSON 解析失败率 38% vs 14%），净效果是 F1 更低。这说明技能文档对生成式模型的"注入"效果取决于模型是否能在保持指令格式的同时应用规则——SFT 的价值正是使模型可靠地同时做到两点。

## 二、核心配方（快速上手）

```
1. 编写技能文档（所有规则，精确、完整）
2. 生成教师数据（Claude + 技能文档 → 推理链）
3. 转换为无技能格式（从训练样本中移除技能文档）
4. LoRA 微调：高质量样本 × 适当轮次 × cutoff_len ≥ 最大输出长度
5. 无技能文档评测
```

关键原则：**数据质量 > 数据数量**。

## 三、第一步：编写技能文档

编写结构清晰的技能文档，包含：
- 所有决策规则（枚举、精确）
- 每条规则的应用方法（输入→判断逻辑→输出）
- 输出格式（正确答案的样例）

技能文档仅在**教师数据生成时**使用，不用于推理。

**SPC 示例**：500 token 的系统提示，包含 Nelson 8 条规则定义 + CPK 公式。

---

## 四、第二步：生成教师数据

使用高质量教师模型（Claude Sonnet 或更强）生成训练样本。

### 训练格式：`with_skill`（ws，教师生成阶段）

```
System: <技能文档——所有规则，完整细节>
User: <任务场景>
Assistant: <think>
[逐步推理，应用每条规则]
</think>
<结构化答案>
```

教师模型见到技能文档，产出高质量的推理链。

### 关键参数

- **N**：每个种子池 200–500 条样本（根据任务复杂度调整）
- **多样性**：每个池使用不同随机种子，避免输入重叠
- **质量验证**：用规则引擎或 oracle 验证答案正确性，**再加入训练集**
- **并发**：3 路并行 API 调用是效率与限速的平衡点

### 难规则专项数据

对于召回率持续偏低的**弱规则**，需要专门构造样本：

| 策略 | 效果 | 适用场景 |
|------|------|---------|
| 增加弱规则样本数量（上采样） | 有限 | 规则本身直觉反直觉（如 rule7） |
| **构造边界对比样本** | 更有效 | 触发边界附近的正例 + 负例配对 |
| 显式推理步骤 | 有效 | 需要数数/精确判断的规则（如 rule2） |

**关键发现（R3-AB-v4）**：rule7 3× 上采样对 rule7 召回无效（0.278，未改善），但意外改善了 rule2（0.552）。结论：上采样仅增加正例数量，不能解决"反直觉边界"问题；真正有效的是正负对比样本对。

## 五、第三步：转换为无技能格式（关键步骤）

**将系统提示中的技能文档移除**，仅保留通用任务描述或空字符串。

```python
def convert_to_noskill(example):
    messages = example["messages"]
    # 替换含技能文档的 system prompt → 通用描述或空字符串
    messages[0]["content"] = ""   # 或通用任务描述（不含规则）
    return example
```

模型必须从 `<think>` 推理链中"学习"规则，而不能依赖系统提示中的规则文档。

### 为什么这步至关重要

如果在系统提示中保留技能文档来训练：模型学会了"查文档"，而不是"记规则"。推理时无文档，性能崩溃。

| 训练格式 | 无技能推理 F1 | 备注 |
|---------|------------|------|
| with_skill（含文档训练） | 0.00–0.05 | 依赖文档 |
| no_skill（无文档训练） | 0.35–0.43 | 已内化 |
| 混合（50/50） | 0.20–0.30 | 部分内化 |

### 多角色 ws 数据的陷阱（Round 3 教训）

R3-B 引入了多角色 ws 数据（质量管理经理、统计分析师等 4 种角色，各 50 条），导致 F1 从 0.430 下降至 0.372。

**原因**：不同角色答案风格各异（数学推导风格 vs 风险描述风格），模型学到了这些风格，输出格式偏移，评测提取器无法识别。

**规则**：所有加入训练的 ws 数据必须通过规则引擎格式验证，答案格式与评测标准一致后才能使用。

## 六、第四步：微调配置

### 模型选择

| 模型 | F1（14B 基准） | 推理显存 | 综合得分 |
|------|-------------|---------|---------|
| 14B bf16 LoRA（推荐） | 0.420 | 96GB | 0.093 |
| 14B QLoRA int4 | 0.394（-6.2%） | ~20GB | **0.427** |
| 14B QLoRA int8 | 0.391（-6.9%） | ~20GB | **0.428** |
| 32B QLoRA int4 | 0.379（-9.8%） | ~45GB | 0.085 |

> **量化结论（Round 3 关键发现）**：int4/int8 量化在复杂推理任务（SPC 规则 + CPK 计算）上损失远超预期（8–9%，目标 ≤2%）。原因：精确数值判断对量化精度敏感，超过一般文本任务。**若任务包含精确数值计算，避免使用量化训练**；若需要低显存部署，接受此精度损失。

**综合得分**最高的是 14B QLoRA int4（0.427），因为推理显存仅 ~20GB（是 bf16 的 1/5）。纯 F1 最高的仍是 14B bf16 LoRA（0.420）。

### LoRA 设置

```yaml
finetuning_type: lora
lora_rank: 128
lora_alpha: 256
lora_target: all
flash_attn: sdpa
bf16: true
```

### 关键：`cutoff_len` 必须超过最大输出长度

**这是最常见的静默训练失败来源。**

```python
from transformers import AutoTokenizer
import numpy as np
tokenizer = AutoTokenizer.from_pretrained(model_path)
lengths = [len(tokenizer(ex["output"])["input_ids"]) for ex in data]
print(f"max={max(lengths)}, p95={np.percentile(lengths, 95):.0f}")
```

设置 `cutoff_len` ≥ 训练样本（输入 + 输出）的 p100 长度。

**SPC 示例**：
- 无技能推理输出：均值 4151 tokens，p95 约 5000+ tokens
- cutoff_len=4096：94% 样本被截断，rule8（输出末尾）召回=0.00
- cutoff_len=5120：0% 截断，所有规则均可学习

**截断样本的危害（Round 3 发现）**：
- 被截断的样本推理链不完整，模型从中学到"提前结束"的行为
- 截断样本 ≠ 短样本，而是"被强制中止的长样本"
- **解决方案**：过滤训练集中超过 cutoff_len 的样本（"去截断"策略），而不是强行保留

R3-AB-v2 对比 R3-AB：去截断后（过滤超长样本），F1 从 0.383 提升至 0.420，CPK 率从 0.835 恢复至 1.000。

### 训练超参数（Qwen3-14B，单卡 H20 验证）

```yaml
num_train_epochs: 5
per_device_train_batch_size: 2
gradient_accumulation_steps: 4      # effective batch = 8（单卡）
learning_rate: 1.0e-4               # 1e-4 优于 5e-5（见下方消融）
lr_scheduler_type: cosine
warmup_ratio: 0.05
weight_decay: 0.01
cutoff_len: 5120
```

**学习率消融（R3-AB-v2-lowlr，Round 3）**：
- lr=1e-4（默认）：F1=0.420
- lr=5e-5（低学习率）：F1=0.409（-0.011）
- **结论**：对 1100 条样本规模，lr=1e-4 已是较优值，无需调低

### 多卡训练

| 方案 | 命令前缀 | 适用场景 |
|------|---------|---------|
| 单卡 | 直接 llamafactory-cli | ≤14B bf16 |
| 3卡 DDP | `FORCE_TORCHRUN=1 CUDA_VISIBLE_DEVICES=0,1,2` | 数据量大（1935条），加速 |

## 八、第六步：分析与迭代

### 诊断表

| 症状 | 可能原因 | 解决方案 |
|------|---------|---------|
| 所有规则召回 ≈ 0 | 训练失败 / 严重截断 | 检查 cutoff_len，验证训练日志 |
| 某规则独占高召回，其余偏低 | 数据不平衡 | 规则级配比调整 |
| 最后一条规则 = 0.00 | 输出截断 | 增大 cutoff_len |
| 无技能推理 F1 远低于有技能 | 训练时仍含技能文档 | 验证 ns 格式转换 |
| CPK 率 < 1.000 | 风格漂移（多格式 ws 数据混入） | 过滤 ws 数据，格式验证后再用 |
| F1 随样本数增加反而下降 | 过拟合（步数过多）| 减少 epoch 或用低学习率 |
| 弱规则（rule2/rule7）持续低于 0.40 | 反直觉边界问题 | 构造正负对比样本对（见第九节）|

### 数据规模 vs 性能

| 阶段 | 样本数 | 主要 F1 | 限制因素 |
|------|--------|--------|---------|
| Round 1（expRR） | 200（纯ns） | 0.358 | cutoff_len=4096 截断 |
| Round 2（expYYY） | ~1000（混合） | 0.430 | 弱规则数据质量 |
| Round 3（R3-AB-v2） | 1131（去截断） | 0.420 | 弱规则突破瓶颈 |
| Round 3（R3-AB-v3） | 1770（+640条） | 0.418 | 新增数据未带来提升 |

**关键洞察**：
1. 从 200 到 1131 条（+5.6×）：F1 从 0.358 → 0.420（+17%）
2. 从 1131 到 1770 条（+57%）：F1 几乎没变（0.420 → 0.418）
3. 去截断（R3-AB 1180条 → R3-AB-v2 1131条，实际减少样本）：F1 从 0.383 → 0.420（+9.7%）

**结论：数据质量（清洁度）> 数据数量。** 去除截断样本比增加更多数据更有效。

## 九、弱规则专项突破策略

### 弱规则定义

持续出现低召回率（< 0.45）的规则：

| 规则 | Round 3 均值召回 | 难度根因 |
|------|--------------|---------|
| rule7 | 0.333 | **反直觉**："过于稳定 = 异常"违反直觉；模型倾向认为平稳 = 正常 |
| rule2 | 0.409 | **假阳性**：9 点同侧在正常过程中也偶尔出现，模型误判率高 |
| rule8 | 0.286 | **分散条件**：8 点各自不在 ±1σ 内，无聚集特征，输出截断后直接归零 |

### rule7 专项策略

**问题本质**：模型对"过于平稳 = 异常"的反直觉逻辑理解不足，倾向于将 15 点全在 ±1σ 内判断为"正常"。

**建议措施**：
1. **正负对比样本对**：每对包含一个"15 点全在 1σ 内（触发）"和一个"第 15 点略超出 1σ（未触发）"，仅最后一点不同
2. **知识型样本**：在推理链中显式写出"连续 15 点全在 ±1σ 内的概率约 0.683^15 ≈ 0.23%，属统计异常"
3. **避免单纯上采样**：R3-AB-v4（3× 上采样）对 rule7 召回无改善（0.278），证明上采样策略对反直觉规则无效

### rule2 专项策略

**问题本质**：模型对"9 点同侧"的判断存在系统性假阳性——正常长序列被误判为 rule2。

**建议措施**：
1. **增加"8 点同侧（未触发）"负样本**：强化边界判断，让模型学会区分 8 点 vs 9 点
2. **显式计数步骤**：在推理链中明确写出"第 N 点使连续同侧点数达到 X"的逐点计数

**Round 3 意外发现**：rule7 3× 上采样意外改善了 rule2（0.552，本轮次高）。推测原因：rule7 样本的推理链中包含大量连续点判断逻辑，间接帮助模型学习了 rule2 的数数技能。

## 十、GRPO 强化训练

### 动机

SFT 的上限受限于教师数据质量。GRPO 直接优化任务指标（rule_f1），理论上可突破教师数据上界。

### 关键约束：max_completion_length

**SPC 任务的 GRPO 失败原因（R3-C）**：

| 参数 | 设置 | 实际输出均值 |
|------|------|-----------|
| max_completion_length | 2048 | — |
| SPC 答案均值 token 长度 | — | **4151 tokens** |

答案长度远超完成限制 → 全部截断（clipped_ratio=1.0）→ 奖励信号为 0 → 策略无法更新 → F1=0.000。

**规则**：GRPO 的 `max_completion_length` 必须 ≥ 任务答案的 **p95 长度**。

```python
# 估算所需 max_completion_length
from transformers import AutoTokenizer
import numpy as np
tokenizer = AutoTokenizer.from_pretrained(model_path)
lengths = [len(tokenizer(ex["output"])["input_ids"]) for ex in train_data]
p95 = np.percentile(lengths, 95)
print(f"建议 max_completion_length ≥ {int(p95 * 1.1)}")  # 留 10% 余量
# SPC: p95 ≈ 5500，建议设置 ≥ 6000
```

### GRPO 配置建议（待 Round 4 验证）

```yaml
max_completion_length: 6000      # SPC 任务，覆盖 95%+ 样本
num_generations: 8               # 每 prompt 采样数
learning_rate: 5e-7              # GRPO 用更低 lr
kl_coef: 0.01
reward_weights:
  rule_f1: 1.0
  cpk_bonus: 0.1                 # |pred_cpk - gt_cpk| < 0.1
  format_bonus: 0.05             # 含规范格式标识符
```

框架选择：trl ≥ 1.3.0（LlamaFactory GRPO 不支持 Qwen3 template）。

## 十一、退化率（Degradation）

SFT 微调后通用能力下降：

| 实验 | F1 | 退化率（6项基准均值） | 主要来源 |
|------|-----|-----------------|---------|
| R3-AB-v2（14B bf16） | 0.420 | 3.08% | gsm8k -18.7% |
| R3-D1（14B int4） | 0.394 | 2.33% | gsm8k -14.5% |
| R3-D2（32B int4） | 0.379 | **0.45%** | 均匀分布，极小 |

**观察**：
- 领域 SFT 主要影响数学推理（gsm8k），其余任务基本稳定
- 32B 模型退化率极低（0.45%），通用能力更鲁棒，但量化后 F1 反而更低
- 退化率与模型参数量负相关（大模型更稳健）

**综合得分公式**（任务性能 × 通用能力保留 / 推理成本）：

```
综合得分 = 任务F1 × (1 - 退化率) / (推理时间_s × 推理卡数 × 单卡显存_GB) × 1000
```

| 实验 | 综合得分 | 主导因素 |
|------|---------|---------|
| R3-D3（14B int8） | **0.4283** | 低显存（~20GB） |
| R3-D1（14B int4） | **0.4266** | 低显存（~20GB） |
| R3-AB-v2（14B bf16） | 0.0934 | F1 高但显存大 |
| R3-D2（32B int4） | 0.0846 | 推理慢（99s） |

## 十二、常见陷阱汇总

1. **cutoff_len 过小** → 静默截断 → 输出末尾规则从未被训练（rule8=0.00）
2. **技能文档留在训练系统提示中** → 模型学会"查文档"，推理时无文档则崩溃
3. **截断样本未过滤** → 不完整推理链污染训练集，比"无此样本"更差
4. **多格式 ws 数据未验证** → 风格漂移，输出格式偏移导致提取率下降
5. **弱规则上采样代替对比样本** → 对反直觉规则（rule7）无效
6. **推理时 max_model_len < cutoff_len** → 生成被截断，答案残缺
7. **GRPO max_completion_length < 答案 p95 长度** → 全截断，零奖励，零学习
8. **过度依赖更大模型量化版本** → 32B int4 F1 低于 14B bf16（量化损失抵消参数优势）
9. **训练步数过多** → 过拟合（200 样本 × 5ep → 125 steps 是 Round 1 甜点，1100 样本需重新校准）
