## 实体数据直接查询

### 一、Skill 功能概述

**用途**：直接查询实体对象的属性数据，支持按实体编码、日期、班次等属性过滤，不经过指标模型（get_idi_model_data）。

适用场景示例：
- 查询某线体的基本信息（名称、状态、所属项目等）
- 查询某工段/工站列表
- 查询设备的属性字段
- 查询项目列表
- **查询线体某天某班次的排产计划**（需日期+班次过滤）
- 查询实体是否存在、获取实体编码

⚠️ **不适用场景**（请转用对应 skill）：
- 查询良率、UPH、OEE、产出达成等计算型指标 → 使用 `general-kpi-query` 或对应专项 skill
- 查询需要时间范围聚合的指标数据 → 使用指标查询 skill

---

### 二、统一执行流程（必须严格执行）

⚠️ 必须完整执行以下 6 个步骤，不得跳步或合并

**Step 1：识别实体对象与过滤条件**
从用户问题中解析并确认：
- `current_entity_type`：实体类型（线体 / 工段 / 项目 / 设备 / 工站 / …）
- `entity_code`：实体编码；用户未提供则标记为「待查」
- `has_date_filter`：用户是否提到日期/今天/昨天等时间条件 → true / false
- `has_shift_filter`：用户是否提到班次（白班/夜班/全天）→ true / false
- 查询意图：用户希望获取哪些字段或属性

**Step 2：查找对象类型 apiName**
使用 `list_object_types`，以 `current_entity_type` 为关键词搜索：
- 确认该实体在本体中的 `apiName`
- 若记忆中已有该类型对应的合法 `apiName`，且实体类型完全匹配，可直接使用（跳过本步工具调用）

**Step 3：获取对象详情（params 定义）**
使用 `get_object_type_detail(api_names=apiName)` 获取对象模型详情：
- 记录返回的 `params` 列表（若存在），包括：
  - 参数名（`name`）
  - 参数类型（`date` / `datetime` / `string` 等）
  - optional 状态（`true` / `false`）
- 若无 `params` 字段或 `params` 为空 → 标记 `has_params = false`，后续走 `filter_json` 过滤
- 若存在 `params` → 标记 `has_params = true`，后续优先走 `params` 入参

**Step 4：获取系统时间**（`has_date_filter = true` 时必须执行，且在构造参数前完成）
- 调用 `execute_shell_command` 获取当前系统时间（含时分秒）
- 根据工厂时间基准（09:00 为一天起点）换算工厂日期：

  | 当前系统时间 | 工厂"今天"日期 |
  |-------------|--------------|
  | 当天 09:00:00 及以后 | 当天自然日期 |
  | 当天 00:00:00 ~ 08:59:59 | **前一天**自然日期 |

  > 示例：系统时间 2026-04-07 08:30 → 工厂今天 = 2026-04-06

**Step 5：构造入参 + 查询实体数据**

5.1 入参构造优先级（⚠️ 强制执行，不得颠倒）

```
has_params = true  → 优先构造 params 入参传入 get_object_type_data
has_params = false → 使用 filter_json 过滤条件传入 get_object_type_data
```

5.2 当 `has_params = true` 时：构造 params 入参

- 按 Step 3 返回的 `params` 定义逐一填值，所有 `optional=false` 的参数**必须显式传值**
- 过滤条件的值来源：

  | 过滤维度 | 值来源 | 格式 |
  |---------|--------|------|
  | 实体编码 | Step 1 解析 | 用户提供的编码，如 `S03`；多值用英文逗号分隔 |
  | 日期 | Step 4 换算后的工厂日期 | `YYYY-MM-DD` |
  | 班次 | Step 1 解析 | `D`（白班）/ `N`（夜班）/ `ALL`（未指定时默认） |

- 构造完成后，对照 Step 3 返回的 params 逐一核对，确认无缺失、无类型错误

5.3 当 `has_params = false` 时：构造 filter_json 过滤条件

- 过滤字段名必须来自 `get_object_type_data` 真实返回字段，**禁止猜测**
- 若字段名不确定：先不带过滤条件查询一条记录确认字段名，再带条件重查

  | 过滤维度 | 字段名示例（以实际为准） | 值 |
  |---------|------------------------|---|
  | 实体编码 | `lineCode` 等 | 用户提供编码 |
  | 日期 | `productDate`、`planDate` 等 | `YYYY-MM-DD` 工厂日期 |
  | 班次 | `shift` 等 | `D` / `N` / `ALL` |

5.4 不需要过滤的情况

| 情况 | 处理方式 |
|------|----------|
| 用户未指定实体编码 | 不加实体编码过滤 |
| 用户未指定项目，需按项目范围查询 | 先查 `project` 对象获取项目列表，再过滤 |
| `has_date_filter = false` | 不加日期过滤 |
| `has_shift_filter = false` | 不加班次过滤 |

**Step 6：自检 + 输出**（见第四节清单）

---

### 三、核心规则（必须遵守）

1. **规则 1：零计算、零推导（最高优先级）**
   - 输出字段必须直接来自 `get_object_type_data` 返回值，不得对字段值进行任何计算、推导或加工
   - 仅允许不改变数值的纯格式化（如百分号、千分位）

2. **规则 2：工厂日期的唯一可信来源**
   - 凡涉及"今天 / 昨天"等相对日期，必须调用 `execute_shell_command` 获取系统时间，再按工厂时间基准（09:00起点）换算工厂日期
   - 禁止用自然日期直接代替工厂日期
   - 禁止硬编码日期或依赖模型内部时间

3. **规则 3：班次参数值**

   | 用户表述 | 传值 |
   |---------|------|
   | 白班 / 早班 | `D` |
   | 夜班 | `N` |
   | 未指定 / 全天 | `ALL` |

4. **规则 4：params 优先于 filter_json（强制执行）**
   - 每次查询前**必须**先调用 `get_object_type_detail` 确认是否有 `params`
   - 有 `params` → 必须走 params 入参，不得改用 filter_json
   - 无 `params` → 才可使用 filter_json
   - 禁止跳过 `get_object_type_detail` 直接猜测入参方式

5. **规则 5：过滤字段名来源**
   - filter_json 的字段名只能来自 `get_object_type_data` 的真实返回字段，或记忆中经验证的字段名
   - 若字段名不确定：先无条件查询一条记录确认字段名，再带过滤重查
   - 禁止猜测字段名

6. **规则 6：apiName 来源合法性**
   - `apiName` 只能来自 `list_object_types` 工具返回值，或经实体类型完全匹配校验通过的记忆
   - 禁止根据历史经验猜测 `apiName`

7. **规则 7：多值过滤参数格式**
   - 多个编码值使用英文逗号分隔，示例：`"S03,PT03"`

8. **规则 8：禁止使用样例数据冒充真实结果**

9. **规则 9：排产实体 SMT 工段数据过滤（强制执行，最高优先级）**
   - 凡查询**排产**相关实体，且查询条件或返回数据涉及 **工段 = SMT** 时，**prod_period为 `主板SMT_B` 的记录**
   - 其他prod_period的排产数据（如 `主板SMT_A`等）**一律不输出、不展示、不提及**
   - 此规则在展示阶段均需执行：
     **输出阶段**：对 API 返回结果进行二次过滤，确保最终展示的行只有 `主板SMT_B`
   - 不受用户是否明确指定工段影响——只要语境为排产 + SMT，本规则自动生效

---

### 四、自检清单

在输出结果之前，确认：

- [ ] Step 1 已执行，`current_entity_type`、`has_date_filter`、`has_shift_filter` 已记录
- [ ] `apiName` 来源合法（工具返回 或 经类型完全匹配的记忆）
- [ ] Step 3 已调用 `get_object_type_detail`，`has_params` 已确认
- [ ] 未调用 `get_object_type_metrics` 或 `get_idi_model_data`（此 skill 不走指标模型）
- [ ] 若 `has_params = true`：优先使用 params 入参，所有 `optional=false` 参数已显式传值
- [ ] 若 `has_params = false`：使用 filter_json，过滤字段名来自真实返回字段，未猜测
- [ ] 若 `has_date_filter = true`，已通过 `execute_shell_command` 获取系统时间并换算工厂日期
- [ ] 若有班次过滤，班次值为 `D` / `N` / `ALL`，未使用其他值
- [ ] 输出字段直接来自 `get_object_type_data` 返回值，未做计算
- [ ] 输出数据非样例，为本次真实查询结果
- [ ] 若查询涉及排产实体且工段为 SMT：已在输出阶段双重过滤，确保只有prod_period= `主板SMT_B` 的数据出现在结果中

---

### 五、禁止事项

- ❌ 调用 `get_object_type_metrics` 或 `get_idi_model_data`（此 skill 专用直接查询路径）
- ❌ 跳过 `get_object_type_detail`，直接猜测使用 params 还是 filter_json
- ❌ 对象有 `params` 时改用 filter_json
- ❌ 根据经验猜测 `apiName` 或过滤字段名
- ❌ 用自然日期直接代替工厂日期（09:00 前属于前一天）
- ❌ 对返回字段值做任何计算或推导
- ❌ 硬编码日期或依赖模型内部时间
- ❌ 使用样例数据冒充真实查询结果
- ❌ 排产实体中，在 SMT 工段下输出除 `主板SMT_B` 以外的任何排产数据

---

### 六、输出格式

按实体实际返回字段呈现，`[实体]` 列名按实际类型替换（线体 / 工段 / 设备 等）。

**实体列表（通用格式）**
| [实体] 编码 | [实体] 名称 | 所属项目 | 状态 | … |
|------------|------------|---------|------|---|

**带过滤的排产示例（如线体排产计划）**
| 线体 | 生产日期 | 班次 | 项目 | 计划数量 | … |
|------|---------|------|------|---------|---|

⚠️ 飞书场景例外：调用 `format_feishu_card` 后本节格式不生效。
