## 一、背景与场景设计

### 1.1 本阶段目标

用最小投入验证**路线二（Skill 内化）**的核心假设，再大规模投入 POC：

- **核心假设**：通过 SFT 训练，可以将 Skill 文档的知识"内化"进模型权重，推理时无需携带 Skill 内容也能正确执行
- **验证指标**：训练后"无 Skill"条件下的准确率 ≥ 训练前"有 Skill"条件的 70%，曲线 R² > 0.6

### 1.2 场景选择：SPC 异常判断技能内化

**场景动机**：当前工厂 AI 系统每次调用 SPC 分析时，必须将完整的 SPC 分析手册（约 2000 tokens）注入 prompt：

```
现状（每次推理）：
  System prompt = "你是工程师。\n\n[SPC分析手册：Nelson规则定义×8 + CPK公式 + 报告模板]"
  User = "[25点数据]"
  → 2500 tokens/次，手册内容明文传输（知识产权风险）

目标（训练后）：
  System prompt = "你是工程师。"  ← 手册已内化进权重
  User = "[25点数据]"
  → 250 tokens/次，节省 90% token 成本，手册内容不出现在 API 请求中
```

**为什么这个场景适合 Demo**：
- 数据 100% 可自动生成（规则引擎直接算标准答案）
- 评测完全自动化（数值对比）
- "无 Skill"基座准确率 ≈ 0%（模型不懂 Nelson 规则）
- "有 Skill"基座准确率 ≈ 30-50%（给定规则定义后可推理）
- 训练目标：无 Skill 条件下达到 60-75%（内化成功）

**SPC 分析技能（Skill 文档内容）**：

```
===== SPC 分析技能手册 =====

一、Nelson 8条控制图规则

| 规则 | 触发条件 | 含义 |
|------|---------|------|
| rule1 | 1点超出 UCL 或 LCL（均值±3σ） | 突发异常 |
| rule2 | 连续9点在均值同侧 | 均值漂移 |
| rule3 | 连续6点单调递增或递减 | 趋势漂移 |
| rule4 | 连续14点交替升降 | 周期干扰 |
| rule5 | 连续3点中2点在同侧2σ外 | 能力早期恶化 |
| rule6 | 连续5点中4点在同侧1σ外 | 均值偏移预警 |
| rule7 | 连续15点在1σ以内 | 分辨率不足/数据造假 |
| rule8 | 连续8点在1σ外且两侧均有 | 双峰分布 |

二、CPK计算

  x̄ = 样本均值    s = 样本标准差
  UCL = x̄ + 3s   LCL = x̄ - 3s
  CPU = (USL - x̄) / (3s)
  CPL = (x̄ - LSL) / (3s)
  CPK = min(CPU, CPL)

  | CPK     | 等级   | 处置       |
  |---------|--------|------------|
  | ≥ 1.67  | 优秀   | 可降检验频次 |
  | 1.33~1.67 | 良好 | 维持现有策略 |
  | 1.00~1.33 | 一般 | 加强监控   |
  | < 1.00  | 不合格 | 立即排查   |

三、输出格式

  1. 逐条检查8条规则，列出所有违规规则及触发点位
  2. 计算并报告 x̄、s、CPU、CPL、CPK
  3. 给出3条以上可执行的处置建议
==========================
```

**三条实验曲线（核心设计）**：

| 条件 | Skill in prompt | 是否训练 | 说明 |
|------|----------------|---------|------|
| **base-no-skill** | ❌ | ❌ | 基座无 Skill，反映当前"不花 token"的效果 |
| **base-with-skill** | ✅ | ❌ | 基座有 Skill，反映"当前每次注入手册"的效果（上界参考） |
| **sft-no-skill** | ❌ | ✅ N1→N4 | SFT 后无 Skill，内化成功的证明 |

> 训练时：prompt 包含 Skill 文档；评测时（sft-no-skill）：不包含 Skill 文档

**核心价值主张**：
- `sft-no-skill` 接近 `base-with-skill` → 证明技能已内化
- `sft-no-skill` >> `base-no-skill` → 证明训练的效果
- token 成本降低 90%，Skill 文档不暴露在 API 请求中

### 1.3 基座模型：Qwen3-8B

**为什么选 8B 而非 14B**：

| 考量 | 说明 |
|------|------|
| 场景匹配 | SPC 分析是高度结构化的领域专用任务，8B 专用模型 > 14B 通用模型——这正是技能内化的价值所在 |
| 推理成本 | 8B 推理成本约为 14B 的 50%，更贴近工厂边缘部署场景 |
| 训练速度 | N4（500条）训练时间：8B ≈ 3 分钟 vs 14B ≈ 6 分钟 |
| 对比故事 | "8B 专用 vs 14B 通用"是有力的 ROI 论据 |

4 × H20（96 GB）环境下资源需求：

| 模型 | 权重显存（BF16） | 推理（TP=1） | LoRA 训练（4卡 DDP） |
|------|---------------|------------|-------------------|
| **Qwen3-8B** | **16 GB** | **1 卡** | **1 卡** |
| Qwen3-14B | 28 GB | 1 卡 | 1 卡 |
| Qwen3-32B | 64 GB | 1 卡 | 1 卡（宽松） |

### 1.4 微调技术：LoRA

500 条数据用 LoRA（低秩适配）：冻结原始权重，注入低秩矩阵 `W_new = W + B×A`，可训练参数约 0.5%。

| 参数 | 值 | 理由 |
|------|----|------|
| rank | 128 | 需学 8 条规则 + CPK + 格式，"新知识"较多 |
| alpha | 256 | = 2×rank，缩放系数经验最优 |
| target | 全部线性层 | attention + FFN 都需要更新 |
| dropout | 0.0 | 小数据集隐式正则已够 |
| epochs | 3 | 500条×3轮≈47步，足以收敛不过拟合 |
| lr | 1e-4 | LoRA SFT 标准值 |
| bf16 | true | H20 原生支持 |
| flash_attn | sdpa | PyTorch 内置，无需额外安装 |

## 二、指标体系说明

### 2.1 为什么用 F1（rule_detection_f1）

SPC 规则检测是**多标签分类**（8条规则可同时触发，每条独立判断）：

```
样本示例：
  ground_truth violations = ["rule1", "rule2", "rule3"]
  model prediction        = ["rule1", "rule3", "rule5"]
  
  TP = {rule1, rule3}    → 正确检出 = 2
  FP = {rule5}           → 误报    = 1  （模型说有但实际没有）
  FN = {rule2}           → 漏报    = 1  （实际有但模型没说）
  
  Precision = TP / (TP + FP) = 2/3 = 0.67  （报了几个是对的）
  Recall    = TP / (TP + FN) = 2/3 = 0.67  （实际有的检出了多少）
  F1 = 2 × P × R / (P + R) = 0.67
```

**为什么不用 Accuracy**：若每次都说"无违规"，正确率 ≈ 20%（正常样本约 20%），但完全没有价值。F1 同时惩罚误报和漏报，是多标签任务的标准指标。

**其他指标**：
- `cpk_mae`：CPK 数值的绝对误差均值，越低越好（理想 < 0.1）
- `cpk_found_rate`：模型给出 CPK 值的比例（1.0 = 总是计算 CPK）
- `has_reasoning_rate`：产出 `<think>` 推理链的比例（训练后预期 100%，**不作为主要评估指标**）
- `inference_time_ms`：单样本平均推理时间（毫秒）
- `train_time_s`：该节点总训练时间（秒）
- `skill_token_cost`：有 Skill prompt 的 token 数 vs 无 Skill 的 token 数（体现成本节省）

### 2.2 N 样本含义

| 字段 | 含义 |
|------|------|
| N1 = 100 | **训练集**样本数（training set size）|
| N2 = 200 | **训练集**样本数 |
| N3 = 300 | **训练集**样本数 |
| N4 = 500 | **训练集**样本数 |
| test = 200 | **测试集**样本数（固定，不变）|

x 轴 = 训练样本数（100/200/300/500），**不是测试集大小**。

### Phase 4：N1~N4 训练 + 评测循环

每个节点（N1 → N4）依次执行：

```bash

# 1. 注册数据集

```

```
R² < 0.60 → 曲线不稳定，检查数据质量
```

## 附录：已知踩坑（来自 reflect v1）

| 场景 | 正确做法 |
|------|---------|
| Qwen3 训练模板 | `template: qwen3`（非 `qwen`） |
| vLLM 部署 | `--tp 1` 避免 TP>1 EngineDeadError |
| 并发评测 | `--concurrency 1` 最稳定 |
| transformers 版本检查 | `DISABLE_VERSION_CHECK=1` |
| 多次 deploy 残留 | deploy 前 `pkill -f spc_eval; kill -9 $(lsof -ti :PORT)` |
| eval 文件被覆盖 | 评测前先 kill 所有 spc_eval 进程 |
| LLaMA-Factory YAML | 每个节点创建独立 YAML，不用 CLI 参数覆盖 |
| 幂律外推超1.0 | 切换饱和修正模型，全序列统一，保证单调 |
| matplotlib CJK 乱码 | 标签全用英文 |
| n_samples 含义混淆 | 用文件名映射训练集大小，不用 JSON 中的 n_samples 字段 |
