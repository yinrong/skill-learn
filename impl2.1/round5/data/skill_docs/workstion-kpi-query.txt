## 工站生产 KPI 指标查询

### 一、Skill 功能概述
用途：查询工站的良率、投入、产出指标，不用于线体。

适用场景示例：
- 用户询问：某天某个工站的良率是多少
- 用户询问：某天某项目某个工站的投入和产出是多少
- 用户询问：某条线体某个工站的产出、良率

⚠️ 不适用场景（请转用对应 skill）：
- 用户询问线体 KPI（良率/产出/OEE/UPH/抛料） → 使用 `line-kpi-query`
- 用户询问项目良率 → 使用 `project-kpi-query`
- 用户询问线体综合运营 → 使用 `line-operation-skill`

---

### 二、统一执行流程（必须严格执行）
⚠️ 所有指标查询，必须完整执行以下 6 个步骤，不得跳步或合并

**Step 1：识别本体对象**
从用户问题中解析并确认：
- 本体对象类型：**工站**（本 skill 仅处理工站）
- 用户需要查询的指标（良率 / 产出 / 投入）
- 日期、班次（未指定则默认今天、全天 ALL）

**Step 2：查找本体对象类型**
使用 `list_object_types` 搜索：
- 确认工站在本体中的 apiName

**Step 3：获取对象主数据**
使用 `get_object_type_data` 查询：
- 获取具体的工站编码
- 用户未指定工站 → 查询全部工站

**Step 4：获取对象指标模型 ID 和参数（关键步骤）**
使用 `get_object_type_metrics` 查询，必须完整获取并记录：
- 该对象关联的所有指标模型 id
- 每个模型对应的 params：
  - 参数名
  - 参数类型（date / datetime / string 等）
  - optional 状态（true / false）
⚠️ 必须记录返回的全部 params，不允许遗漏

**Step 5：通过"对象指标与模型映射关系"调用模型（严格规则）**

5.1 确定模型 ID 与时间参数类型（强制）
- 模型 ID 必须且只能通过下方第三节「对象指标与模型映射关系表」确定，禁止猜测、替换
- 时间参数类型必须且只能来源于 Step 4 中 `get_object_type_metrics` 返回的 params 定义
- 严禁根据模型 ID、参数名称、历史经验或上下文示例自行推断时间参数类型

5.2 时间参数类型规则
- 若时间参数类型 = "datetime" → 必须使用 datetime 类型规则
- 若时间参数类型 = "date" → 必须使用 date 类型规则

5.3 参数构造强制规则
- 所有 optional=false 的参数必须显式传值，禁止使用默认值
- 构造完成后：必须逐一对照 **Step 4** 返回的 params，确认无缺失、无类型错误

**Step 6：Skill 调用自检（⚠️重点）**
在输出结果之前，快速检查：
- [ ] 是否完整严格按顺序执行 Step 1–5
- [ ] 是否正确识别了工站对象（非线体/项目）
- [ ] 是否使用了正确的指标模型 ID（来自第三节映射表）
- [ ] 时间范围是否符合 Step 5.2 的参数类型规则
- [ ] 参数是否完整（对照 **Step 4** 返回的 params 逐个检查）
- [ ] 班次参数是否正确设置
- [ ] 输出是否为模型原始数据（未二次加工）

### 四、核心规则（必须遵守）

1. **规则 1：零计算、零推导、零润饰（最高优先级，强制执行）**
   - 指标及其组成字段，严禁任何形式的计算、推导、补算、估算、插值、回填、单位换算、同比/环比、跨模型聚合或合成
   - 结果必须仅来自一次合法的 `get_idi_model_data` 调用；仅允许原样使用模型返回的字段与数值进行展示（可做不改变数值的纯格式化，如百分号、千分位）

2. **规则 2：今日日期的唯一可信来源**
   - 涉及"今天 / 昨天"等时间判断时：必须调用 `execute_shell_command` 获取真实系统日期
   - 禁止依赖模型自身时间，禁止主观推断或硬编码日期

3. **规则 3：时间范围规则（⚠️重点）**

   **3.1 识别逻辑流程（强制）**
   获取系统时间 → 计算"昨天""今天"日期 → 判断参数类型（date / datetime）
   - date 类型 → 直接用日期字符串（YYYY-MM-DD）
   - datetime 类型 → 根据班次转换为工厂时间格式
   - 用户未指定班次 → datetime 默认使用"全天"（09:00 - 次日 09:00）

   **3.2 参数类型对照表**

   | 日期类型     | 参数格式              | 示例（假设昨天=2026-03-19）                                          | 说明                         |
   |--------------|-----------------------|----------------------------------------------------------------------|------------------------------|
   | **datetime** | `YYYY-MM-DD HH:MM:SS` | 全天：startTime=`2026-03-19 09:00:00`，endTime=`2026-03-20 09:00:00` | `>= startTime AND < endTime` |
   | **datetime** | `YYYY-MM-DD HH:MM:SS` | 白班：startTime=`2026-03-19 09:00:00`，endTime=`2026-03-19 21:00:00` | 当天 09:00-21:00              |
   | **datetime** | `YYYY-MM-DD HH:MM:SS` | 夜班：startTime=`2026-03-19 21:00:00`，endTime=`2026-03-20 09:00:00` | 当天 21:00-次日 09:00         |
   | **date**     | `YYYY-MM-DD`          | start_date=`2026-03-19`，end_date=`2026-03-19`                       | 生产日概念，直接用日期字符串  |
   | **date**     | `YYYY-MM-DD`          | start_date=`2026-03-18`，end_date=`2026-03-20`                       | 日期范围查询                  |

   **3.3 工厂时间基准（仅适用于 datetime 类型）**
   - 白班：09:00 - 21:00
   - 夜班：21:00 - 次日 09:00
   - 全天：09:00 - 次日 09:00（用户未指定班次时默认使用）

4. **规则 4：参数完整性检查（⚠️重点）**
   在调用 `get_idi_model_data` 之前，必须执行以下检查：
   - 读取 **Step 4** 返回的所有 params 信息
   - 逐个确认每个 optional=false 的参数都有传值
   - 如果某个参数没有传值，即使有默认值也不允许，必须显式传递
   - 构造完参数后，列出完整的 params_json 与 **Step 4** 返回的参数进行逐一核对

5. **规则 5：班次参数（shift）**
   - D：白班 / N：夜班 / ALL：全天
   - 当模型存在 shift 参数且用户未指定班次 → 传 ALL

6. **规则 6：工站产出模型特殊筛选**
   - if 工段 = SMT then 结果必须筛选 process = '主板SMT_B' else 结果不需要筛选 process

7. **规则 7：项目与线体缺省逻辑**
   - 用户没有指定项目 → 先查询全部项目（`get_object_type_data` 查 `project` 对象）
   - 用户没有指定线体 → 查询全部线体

8. **规则 8：多值参数格式**
   - 多个项目 / 线体：使用英文逗号分隔，示例：`"P3,N3,O1"`

9. **规则 9：禁止使用样例数据冒充真实结果**
