# 技能内化方法论 v2：通用框架

**适用范围：将任意结构化专业技能编入语言模型权重**
**版本：v2.0（2026-05-09）**

---

## 一、核心概念

### 什么是"技能内化"

| 术语 | 定义 |
|------|------|
| **技能（Skill）** | 一套结构化的程序性知识——规则、判断树、操作流程——使智能体能执行特定领域任务 |
| **内化（Internalization）** | 模型推理时**不依赖**外部技能文档，直接从权重中调用技能 |
| **教师数据（Teacher Data）** | 由强模型（如 Claude）结合技能文档生成的高质量推理链样本 |

### 与其他方案的本质区别

| 方案 | 推理时技能文档 | 适用场景 | 局限 |
|------|--------------|---------|------|
| RAG / 上下文注入 | 每次携带 | 文档频繁更新 | Token 成本高、有泄露风险 |
| 工具调用 | 按需查询 | 需要实时数据 | 依赖外部基础设施 |
| **技能内化（SFT）** | **不需要** | 规则稳定、高频调用 | 技能变更需重训 |
| GRPO 强化 | 不需要 | 有明确奖励信号 | 需设计 reward 函数 |

---

## 二、技能类型分类

不同技能类型决定了训练数据格式设计策略：

| 类型 | 特征 | 示例 | 内化策略 | 内化上限 |
|------|------|------|---------|---------|
| **A：纯规则/算法型** | 输入→确定性输出，无需外部信息 | SPC 规则、ICD 编码、合规检查 | 完全内化 | 接近 100% |
| **B：知识密集型** | 依赖大量领域事实，规则稳定 | 法律条文适用、医学诊断 | 规则内化 + RAG 补 facts | 中等（取决于知识密度） |
| **C：工具调用型** | 核心逻辑可内化，部分步骤需工具 | 数据分析（读 CSV）、代码执行 | 内化"何时/如何用工具"的框架 | 高（工具框架），低（工具结果依赖） |
| **D：实时数据型** | 结果依赖当前状态，不可预先学习 | 股价查询、实时库存 | 仅内化查询策略和结果解读 | 低（必须保留工具调用） |

> **原则**：技能中"哪部分是规则/逻辑"可以内化；"哪部分是实时数据"必须保留工具调用。

## 四、第一步：技能文档设计

### 结构要求

技能文档是教师数据生成的唯一依据，仅在训练阶段使用：

| 必要元素 | 说明 |
|---------|------|
| 规则枚举 | 所有决策规则，精确、完整，无歧义 |
| 触发条件 | 每条规则的输入条件（精确定义，避免"通常"等模糊词） |
| 应用步骤 | 输入→判断→输出的完整流程 |
| 输出格式 | 正确答案的样例（字段名、格式、枚举值） |

### 不同技能类型的文档模板

**类型 A（纯规则型）**
```
===== 技能：[技能名称] =====
一、规则列表
  rule_id | 触发条件（精确定义） | 含义
  ...

二、判断步骤
  Step 1: 计算基础参数
  Step 2: 逐条检查规则
  Step 3: 输出格式：{"rules": [...], "result": ...}

三、边界说明（重要）
  - 规则 X 与规则 Y 的区别：...
  - 恰好在边界的处理方式：...
=========================
```

**类型 C（工具调用型）**
```
===== 技能：[技能名称] =====
一、可用工具
  - tool_name: 调用时机、入参格式、出参解读

二、决策框架
  满足条件 A → 调用 tool_1 → 根据结果判断 ...
  满足条件 B → 直接推理（不需要工具）

三、输出格式
  ...
=========================
```

> **技能文档验证**：批量生成训练数据前，先用 3–5 个样本做试调用，确认教师模型能够严格按文档格式输出。文档中的歧义或格式不清晰会在此阶段暴露。

## 五、第二步：教师数据生成

教师数据生成是**两阶段流水线**：先用输入场景生成器制造多样化输入，再用教师模型调用技能文档生成推理链。

### 阶段 1：输入场景生成器

用随机种子控制多样性——每个种子生成一个独立的输入场景，确保覆盖不同规则触发组合。**生成器的输出会被格式化为 User 消息**，连同技能文档一起送进教师模型。

不同技能类型的生成策略和 User 消息结构：

**类型 A：纯规则/算法型**

数据完全由代码程序化生成，不依赖任何外部资源：

```
# 生成过程（代码）
mu, sigma = rng.uniform(45, 55), rng.uniform(2, 5)
data = [rng.gauss(mu, sigma) for _ in range(25)]
# 程序注入目标规则触发条件（如让第8-16点同侧）

# 最终 User 消息
请分析以下数据点，判断是否触发规则：
数据：[45.2, 46.8, 47.3, ...]
USL=55.0, LSL=45.0
```

**类型 B：知识密集型**

从已有语料库（合同库、案例库、知识库）采样真实文本片段，无需生成：

```
# 从语料库随机抽取一段合同文本
text = corpus.sample(rng)

# 最终 User 消息
请审查以下合同条款是否合规：
[条款文本原文，来自语料库]
```

若无现成语料库，可用 LLM 预先批量生成多样化场景文本，存入语料库后再采样。

**类型 C：工具调用型**

合成用户问题 + 预构造工具响应。工具响应可以是真实调用结果，也可以是程序生成的模拟数据：

```
# 生成一个需要工具的问题场景
question = f"分析 {rng.choice(datasets)} 中 Q{rng.randint(1,4)} 的趋势"
tool_response = generate_mock_csv_data(rng)   # 预构造工具返回

# 最终 User 消息（含预设工具交互）
分析 sales_2025.csv 中 Q3 的销售趋势
[TOOL_RESULT 在 Assistant 侧展开]
```

**类型 D：实时数据型**

从历史数据库中采样快照，将实时数据"固化"为训练样本：

```
# 从历史记录中采样一条快照
snapshot = history_db.sample(rng)

# 最终 User 消息
当前库存快照（2025-03-15 14:30）：
SKU-123：剩余 15 件，安全库存 50 件，补货周期 7 天
请判断是否需要触发补货流程。
```

训练集与测试集**必须使用不同种子池**，避免数据泄露。

### 阶段 2：教师模型调用（通用训练格式 with_skill）

将阶段 1 的场景 + 完整技能文档组合为 prompt，调用强模型生成带推理链的训练样本：

```
System: <技能文档——所有规则，完整细节>
User:   <任务场景 + 输入数据（来自阶段 1）>
Assistant: <think>
  [Step 1: 解析输入]
  [Step 2: 逐条应用规则/调用工具]
  [Step 3: 综合判断]
</think>
<结构化输出，与评测格式严格一致>
```

### 阶段 3：质量验证

生成后**必须用规则引擎或 oracle 验证答案正确性**，不合格样本直接丢弃，不入训练库。

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 样本量 N | 200–1000 | 从 200 开始，不足再扩 |
| 并发数 | 3–5 | API 限速与效率的平衡点 |
| 随机种子 | 与测试集隔离 | 避免数据泄露 |

### 工具调用型技能的特殊处理

当技能包含工具调用时，教师数据中保留完整工具调用链：

```
<think>
  分析输入，判断需要调用 [tool_name]
  入参：{"param": "value"}
</think>
[TOOL_CALL]: tool_name({"param": "value"})
[TOOL_RESULT]: {"output": ...}
<think>
  根据工具结果继续推理...
</think>
<最终输出>
```

内化后，模型学会的是：**何时调用、传什么参数、如何解读结果**，而非工具本身的逻辑。

## 六、第三步：格式转换（关键步骤）

**将系统提示中的技能文档移除**，仅保留通用任务描述：

```python
def convert_to_noskill(example):
    messages = example["messages"]
    messages[0]["content"] = ""   # 移除技能文档，保留空字符串或通用描述
    return example
```

### 为什么这步是关键

| 训练格式 | 推理时行为 | 无技能文档 F1 |
|---------|-----------|-------------|
| with_skill（含文档训练） | 依赖文档，无文档则崩溃 | 0.00–0.05 |
| **no_skill（无文档训练）** | **从权重调用技能** | **0.35–0.43** |
| 混合 50/50 | 部分内化，不稳定 | 0.20–0.30 |

### 各类型技能的格式转换策略

| 技能类型 | 转换策略 |
|---------|---------|
| 纯规则型 | 直接移除技能文档 |
| 知识密集型 | 移除规则文档，保留通用领域描述 |
| 工具调用型 | 移除技能文档，但**保留工具声明**（函数签名保留，规则文档移除） |
| 实时数据型 | 保留工具声明 + 数据解读指引 |

## 七、第四步：微调配置

### LoRA 核心参数

| 参数 | 推荐值 | 含义 |
|------|--------|------|
| lora_rank | 64–128 | 低秩矩阵的秩 r，决定可训练参数量 |
| lora_alpha | 2× rank | 缩放系数，实际缩放倍数 = alpha/rank |
| lora_target | all | 对全部线性层（QKV、FFN）挂载 LoRA |
| bf16 | true | bfloat16 精度，H20/A100 标准选择 |

### 最重要的配置：cutoff_len

**静默训练失败最常见的来源。**

```python
# 上训练前必做：检查输出长度分布
from transformers import AutoTokenizer
import numpy as np
tokenizer = AutoTokenizer.from_pretrained(model_path)
lengths = [len(tokenizer(ex["output"])["input_ids"]) for ex in data]
print(f"max={max(lengths)}, p95={np.percentile(lengths, 95):.0f}")
# 设置 cutoff_len ≥ max(lengths)
```

| cutoff_len 设置 | 后果 |
|---------------|------|
| 低于输出最大长度 | 推理链被截断，输出末尾内容从未被训练 |
| 等于 p95 | 5% 样本截断，长推理链规则/步骤丢失 |
| ≥ p100 | 正常，所有样本完整训练 |

### 推荐超参数（通用起点）

```yaml
num_train_epochs: 3–5
per_device_train_batch_size: 2
gradient_accumulation_steps: 4
learning_rate: 1.0e-4
lr_scheduler_type: cosine
warmup_ratio: 0.05
cutoff_len: max_output_tokens × 1.2  # 留 20% 余量
```

## 八、第五步：评测协议

### 测试集生成

与训练数据使用**同一套输入场景生成器**，但使用独立的随机种子池（两者不重叠）。测试集规模建议 ≥ 200 条，对应 F1 置信区间约 ±0.01。

```python
# 训练集种子：0–999，测试集种子：10000–10199（不重叠）
train_data = generate(seeds=range(0, 1000))
test_data  = generate(seeds=range(10000, 10200))
```

### 始终无技能文档评测

```python
system_prompt = ""   # 或通用任务描述，不含任何规则
```

### 评测指标设计原则

| 维度 | 通用指标 | 含义 |
|------|---------|------|
| **任务准确性** | F1 / Exact Match / 准确率 | 根据任务类型选择 |
| **格式可用性** | 结构化输出提取率 | 答案能否被程序解析 |
| **稳定性** | 多次采样方差 | 生产环境可靠性 |
| **通用能力保留** | 退化率（6项基准均值） | SFT 对通用能力的影响 |

### 指标选型建议

| 任务类型 | 主指标 | 辅助指标 |
|---------|--------|---------|
| 多标签分类（如规则检测） | macro F1 | per-class recall、Exact Match |
| 生成+提取（如报告+数值） | F1 + 提取率 | 数值 MAE |
| 工具调用正确性 | 工具选择准确率 | 参数正确率 |
| 开放式推理 | 人工评分 / LLM-as-Judge | ROUGE / BERTScore |

## 九、第六步：分析与迭代

### 通用诊断表

| 症状 | 可能原因 | 解决方案 |
|------|---------|---------|
| 所有指标接近 0 | 训练失败 / cutoff_len 严重截断 | 检查日志，增大 cutoff_len |
| 格式提取率低 | 多样式训练数据混入 | 格式验证过滤，统一输出格式 |
| 无技能 F1 << 有技能 F1 | 训练时仍含技能文档 | 验证 no_skill 格式转换 |
| 特定规则/步骤始终为 0 | 该内容在训练输出末尾被截断 | 增大 cutoff_len，或过滤截断样本 |
| 增加数据量无提升 | 数据质量问题（截断、格式污染） | 清洗数据优先于扩充数据 |
| 工具调用乱报 | 训练数据工具调用格式不一致 | 统一工具调用格式，增加负样本 |

### 数据策略优先级

```
数据质量（清洗截断/验证格式）
    > 针对性边界样本（弱规则/边界条件）
        > 数据数量（简单扩充）
```

## 十、常见陷阱

1. **cutoff_len 过小** → 输出末尾内容从未被学习
2. **技能文档留在训练 system prompt** → 模型依赖文档，推理时崩溃
3. **截断样本未过滤** → 不完整推理链污染训练集，比无此样本更差
4. **多格式训练数据未验证** → 风格漂移，输出无法被解析
5. **工具调用型技能：移除了工具声明** → 模型无法知道可用工具
6. **推理时 max_model_len < cutoff_len** → 生成被截断，答案残缺
7. **GRPO max_completion_length < 答案 p95 长度** → 全截断，零奖励，零学习
8. **训练步数过多** → 过拟合，泛化能力下降

## 附录 A：监督微调（SFT）原理

### A.1 什么是 SFT

SFT（Supervised Fine-Tuning）：用标注好的（输入，输出）对，让模型学会在给定输入下生成期望输出。

### A.2 训练过程

```
输入（input_ids）: [system + user + assistant_prefix]
标签（labels）:   [-100, -100, ..., token_1, token_2, ..., token_n]
                   ↑ 输入部分不计算 loss    ↑ 只对输出部分计算 loss
```

Loss = 交叉熵，衡量模型预测的 token 概率分布与真实 token 的差距：

```
Loss = -Σ log P(token_i | context)
```

**关键**：模型只从 Assistant 输出部分学习，输入部分不参与梯度计算。

### A.3 LoRA：低秩适配

原始权重矩阵 W（维度 d×k）保持冻结，添加低秩分解：

```
W' = W + (alpha/rank) × B·A
          B: d×r（可训练）
          A: r×k（可训练）
          r << min(d, k)
```

| 参数 | 作用 |
|------|------|
| rank（r） | 控制表达能力（参数量），越大越强但越慢 |
| alpha/rank | 控制更新幅度，与 rank 解耦，独立调节 |

挂载位置（`lora_target: all`）：

| 模块 | 层名称 |
|------|--------|
| 注意力机制 | q_proj / k_proj / v_proj / o_proj |
| 前馈网络（FFN） | up_proj / gate_proj / down_proj |

## 附录 B：GRPO 强化训练原理

### B.1 动机

SFT 的上限由教师数据质量决定。GRPO 直接优化任务指标（reward），理论上可突破教师数据上界。

### B.2 完整训练循环

```
┌──────────────────────────────────────────────────────────┐
│                    GRPO 训练循环                           │
│                                                          │
│  [1] 输入 prompt（问题，无答案）                           │
│       ↓                                                  │
│  [2] 当前模型 采样 N 个候选输出（num_generations=8）        │
│       ↓                                                  │
│  [3] Reward 函数 对每个输出打分（0~1）                     │
│       ↓                                                  │
│  [4] 计算相对优势：advantage_i = reward_i - mean(rewards) │
│       ↓                                                  │
│  [5] 策略梯度更新：强化高分输出，抑制低分输出               │
│  [5'] KL 惩罚：防止偏离参考模型太远（kl_coef 控制）         │
│       ↓                                                  │
│  [6] 重复直到收敛                                         │
└──────────────────────────────────────────────────────────┘
```

### B.3 模型输入

```
System: ""（无技能文档，测量内化程度）
User:   <任务场景 + 输入数据>
```

与 SFT 推理时完全相同的格式，无技能文档。

### B.4 模型输出

模型采样 N 个完整回答（num_generations 个），每个都是独立的推理链 + 答案：

```
候选输出 1: <think>...推理链A...</think> <答案格式>
候选输出 2: <think>...推理链B...</think> <答案格式>
...
候选输出 N: <think>...推理链N...</think> <答案格式>
```

### B.5 Reward 函数设计

Reward 函数是 GRPO 的核心，需要针对任务设计：

| 奖励组件 | 计算方式 | 示例（SPC 任务） |
|---------|---------|----------------|
| **主奖励** | 与 Ground Truth 的 F1/准确率 | rule_detection_f1（0~1） |
| **格式奖励** | 输出格式是否可解析 | 含规范格式标识符 +0.05 |
| **辅助奖励** | 任务特定的数值准确性 | \|pred_cpk - gt_cpk\| < 0.1 则 +0.1 |

```python
def reward_fn(output, ground_truth):
    # 1. 主奖励：任务 F1
    pred = extract_answer(output)          # 提取结构化答案
    f1 = compute_f1(pred, ground_truth)    # 与标准答案对比

    # 2. 强制推理链（缺失则乘零）
    if "<think>" not in output:
        return 0.0

    # 3. 格式奖励
    format_bonus = 0.05 if is_parseable(output) else 0

    # 4. 数值精度奖励（任务特定）
    cpk_bonus = 0.1 if abs(pred.cpk - ground_truth.cpk) < 0.1 else 0

    # 5. 空预测惩罚（封堵捷径）
    empty_penalty = -0.3 if (pred.violations == [] and ground_truth.violations != []) else 0

    return f1 + format_bonus + cpk_bonus + empty_penalty
```

> ⚠️ **R3-C 实验教训（2026-05-12）**：  
> 修复四个工程 bug 后，GRPO 正常训练 18h（255 步），但 F1 从 0.420 跌至 **0.003**，has_reasoning_rate=0.0。  
> 根因：reward 函数允许"始终预测空违规 + 正确 CPK"捷径（期望 reward≈0.6），比真正检测规则更稳定。模型在 3 epoch 内完全收敛到该捷径。  
> **必须封堵所有高收益捷径**，否则 GRPO 比不训练更差。建议：空预测惩罚 -0.3 + 无推理链乘零 + KL beta 提高到 0.05。

### B.6 关键约束：max_completion_length

**GRPO 常见工程失败原因**：

| 参数 | 设置错误时 | 后果 |
|------|-----------|------|
| max_completion_length < 答案 p95 长度 | 所有输出被截断 | clipped_ratio=1.0，reward=0，模型无法更新 |
| reward 函数存在高收益捷径 | 模型收敛到捷径 | 任务性能灾难性下降，has_reasoning_rate=0 |
| KL beta 过小（<0.01） | 模型大幅偏离 SFT | SFT 能力被灾难性覆盖 |

```python
# 设置前必须检查
p95 = np.percentile(output_lengths, 95)
max_completion_length = int(p95 * 1.1)   # 留 10% 余量

# reward 函数设计检查清单：
# □ 是否存在"始终输出默认值"能获得中等奖励的捷径？
# □ 是否有惩罚懒惰输出（空预测、无推理链）的机制？
# □ KL beta 是否足够（建议 0.01~0.1）？
```

## 附录 C：评测指标体系

### C.1 多标签分类（如规则检测）

模型输出一个规则集合，与 Ground Truth 集合对比：

```
Ground Truth: {rule2, rule5}
预测结果:     {rule2, rule7}

TP（正确报警）= 1   → rule2
FP（误报）    = 1   → rule7（多报了）
FN（漏报）    = 1   → rule5（漏掉了）

Precision = TP / (TP+FP) = 1/2 = 0.50  （报的里面有多少是对的）
Recall    = TP / (TP+FN) = 1/2 = 0.50  （真实异常里找到了多少）
F1        = 2×P×R / (P+R) = 0.50
```

### C.2 Exact Match（完全正确率）

预测集合与 Ground Truth 完全一致才算对，多标签任务的严格指标：

```
{rule2, rule5} vs {rule2, rule7} → 0（不完全相同）
{rule2, rule5} vs {rule2, rule5} → 1（完全相同）
```

Exact Match = 完全正确样本数 / 总样本数

> 与 F1 的关系：F1 高但 EM 低，说明模型经常"部分对"（找到一些但不全）；EM 高则 F1 一定高。

### C.3 退化率

领域 SFT 后，通用能力的下降幅度：

```
退化率 = Σ (基准任务得分下降) / 基准任务数
```

常用基准：gsm8k（数学）、hellaswag（常识）、mmlu（知识）等。
