### 第3轮（2026-04-23 下午至晚）：核心突破

**关键改进**：
1. **数据策略**：引入 25% no-skill 样本（system 字段不含 Skill 文档，强制参数记忆）
2. **教材样本**：由 `gen_textbook.py` 生成约 120 条详细讲解样本（500~3000 字/条）
3. **训练目标**：lora_target=q,v,up,down,gate_proj（全部含 FFN）
4. **基座升级**：Qwen3-14B（14B 预训练 SPC 知识优于 8B）
5. **Epoch 调整**：根据 no-skill 曝光次数（目标 ~600 次）确定各节点 epoch 数

**no-skill 曝光次数分析**：

| 模型 | no-skill样本 | epochs | 曝光次数 | 梯度步数 | F1 |
|------|------------|--------|---------|---------|-----|
| N1 | 76 | 8 | 608 | 152 | **0.100** |
| N2 | 101 | 6 | 606 | 192 | **0.119** |
| N3 | 126 | 5 | 630 | 220 | 0.064 |
| N4 | 176 | 3 | 528 | 207 | 0.090 |

~600 次曝光 + ~150~220 梯度步是甜区；过多（N4 初版 8ep=1408 次）导致过拟合崩塌（F1≈0）。

**调试过程**：
- N2/N3/N4 第一版（4ep/4ep/8ep）评测 F1 均=0.000
- 发现根因：no-skill 曝光次数不足（N2/N3 ~400~500 次），或过训（N4 1408 次）
- 调整 epoch 后重训 N2（6ep）、N3（5ep）、N4（3ep），N1/N2 突破零值

**评测器修复**：模型在无 Skill 时输出中文格式（非英文 rule1），需扩展提取器：
- N1：英文 `rule1` / `Rule 1`（带空格）
- N2：中文 `第1条`（阿拉伯数字）
- N3：中文 `规则②`（Unicode 圆圈数字 ①~⑧）

`extractor.py` 增加三套正则，全部兼容。

## 三、关键问题与解决方案

### 问题 1：幂律外推超越 1.0（第1轮，返工3次）

- **现象**：pred@100K=4.07，严重高估
- **原因**：N∈[100,500] 拟合 b≈1.69，外推 200× 后爆炸
- **修复**：引入饱和修正模型（alpha=0.65），全序列统一切换，保证单调递增

### 问题 2：matplotlib CJK 字体乱码

- **原因**：容器无 CJK 字体，DejaVu Sans 不含中文
- **修复**：所有图表标签改为英文（Fig1/Training samples/rule_f1 等）

### 问题 3：vLLM TP>1 并发崩溃（EngineDeadError）

- **原因**：vLLM 0.19.1 TP>1 共享内存广播存在竞态条件
- **修复**：一律 `--tp 1`，`--concurrency 1`，14B 模型在单张 96GB H20 可完整加载

### 问题 4：N2/N3 F1=0（中文输出格式未被提取器识别）

- **现象**：N2 输出 `第1条` 而非 `rule1`，旧提取器匹配失败
- **根因**：enable_thinking=False 时 Qwen3-14B SFT 输出中文 SPC 术语
- **修复**：扩展提取器支持三种格式；保持 enable_thinking=False（快，~5s/样本）

### 问题 5：N4 8ep 过拟合（F1=0.005，输出全触发或全空）

- **现象**：1408 次 no-skill 曝光 + 552 梯度步，训练 loss=0.226 但 F1≈0
- **根因**：过拟合训练分布，无 Skill 时输出崩塌（要么全预测触发，要么全空）
- **修复**：改为 3 epochs（207 步，528 曝光次数），N4 F1 恢复到 0.090

### 问题 6：N3 Scaling 下凸（N3 F1=0.064 低于 N2 的 0.119）

- **现象**：训练样本增多但效果反而变差
- **根因**：未完全定位；可能是规则覆盖分布不均匀（N3 主导 rule2，N1 全覆盖）
- **教训**：需确保各 N 版本训练数据均衡覆盖全部 8 条规则

### 问题 7：孤儿 vLLM 进程占用 89GB VRAM

- **现象**：GPU 0 有 PID=3022124（PPID=1，来自前日会话）常驻占用全卡
- **修复**：`kill 3022124`，释放 97GB

## 四、执行反思

### 4.1 计划设计的误差

**基座预测偏高**：计划中预估 `base-with-skill` rule_f1≈0.25~0.50，实际仅 0.109（Qwen3-14B）。Nelson 规则是高度专业的 SPC 术语，base 模型 zero-shot 效果接近 0 是正常起点，计划数字偏乐观。

**SFT 目标偏高**：计划中验收标准为 `N4 sft-no-skill ≥ base-with-skill × 0.70`（即 F1≥0.077），实际 N4 F1=0.090，勉强通过。但 N4 规则覆盖严重不均匀（rule3~8 几乎为零），质量上不达预期。

**Scaling 假设过于乐观**：计划预期 R²>0.60、单调递增曲线。实际第3轮 R²=0.168、非单调，原因是 N3 模式崩塌。第1轮（all-skill 训练）R²=0.978，但不代表 no-skill 内化场景同样平滑。

### 4.2 关键设计决策

**no-skill dropout 是最重要的发现**：训练样本中混入 25% 无 Skill 版本是内化成功的核心条件——强制模型在无提示时也能激活规则知识。这个设计在原计划中未提及，是第3轮迭代中发现的。

**FFN 层必须包含在 LoRA target**：原计划建议 `lora_target: all`，第2轮复盘时发现必须显式包含 up/down/gate_proj（知识注入层），否则训练只改变注意力模式，规则知识无法存储。

**模型大小的权衡**：计划推荐 Qwen3-8B（成本低），但实际执行第1轮时已换用 14B（8B 预训练 SPC 知识弱）。代价是推理成本翻倍；收益是内化成功率更高。

### 4.3 评测链路的额外复杂度

真实执行中，评测器本身成为主要 debug 对象：模型输出格式（中英文、带空格/不带空格、圆圈数字）多样化，需要多次修改提取器。这在计划中完全未预见。

建议：在训练数据生成阶段即统一输出格式为英文 `rule1`/`rule2`，避免评测时格式多样化问题。

### 4.4 多轮迭代的成本

| 轮次 | 主要问题 | 结果 |
|------|---------|------|
| 第1轮（Apr 22） | 无 no-skill dropout，基础链路验证 | F1=0.112，R²=0.978，Go |
| 第2轮（Apr 23 上午） | 数据策略调整，中途发现设计缺陷 | 归档 |
| 第3轮（Apr 23 下午） | no-skill dropout + FFN LoRA + 教材样本 | F1 全非零，部分模式崩塌 |

三轮合计约 14 小时（含 GPU 等待）。若在第1轮设计时即包含 no-skill dropout，可节省约 6 小时。

## 五、后续建议

1. **统一输出格式**：训练数据 output 字段强制使用英文 `rule1`/`rule2` 标识符，消除中文格式 drift
2. **规则覆盖均衡**：检查各 N 版本训练数据的 per_rule 分布，保证 rule1~rule8 各有足量样本
3. **N1 是当前最可靠基准**：唯一覆盖全部 8 条规则（F1=0.100，all recall > 0），可用于 route2.2 迭代起点
4. **量化甜区**：当前经验值"~600 no-skill 曝光 + ~200 梯度步"需在 N=1K~5K 范围验证是否成立
5. **enable_thinking=True 评测**：虽然速度慢（~60s/样本），但可避免中文 format collapse；有条件时做对比实验
6. **vLLM 升级**：0.19.1 TP>1 有 known bug，升级后重测 TP=2/4 稳定性
7. **黄金样本集**：引入 20~30 条人工标注样本做额外验证，避免"自己验自己"

### 步骤 2：打印测试集输入/输出（随机抽样展示）

```bash
cd /home/yinrong/phase2.1
python3 - <<'EOF'
import json, random, urllib.request, time

PORT = 8042
TEST_FILE = "data/demo/test.jsonl"
N_SAMPLES = 5          # 展示样本数，可改为更大值
SYSTEM_NO_SKILL = "你是一名SPC工程师。"   # 无 Skill 文档（内化效果测试）

samples = [json.loads(l) for l in open(TEST_FILE)]
random.seed(42)
chosen = random.sample(samples, N_SAMPLES)

for i, s in enumerate(chosen, 1):
    messages = [
        {"role": "system", "content": SYSTEM_NO_SKILL},
        {"role": "user",   "content": s["instruction"] + "\n\n" + s["input"]},
    ]
    body = json.dumps({
        "model": "default", "messages": messages,
        "max_tokens": 2048, "temperature": 0.0,
        "chat_template_kwargs": {"enable_thinking": False},
    }).encode()
    req = urllib.request.Request(
        f"http://localhost:{PORT}/v1/chat/completions",
        data=body, headers={"Content-Type": "application/json"},
    )
    t0 = time.time()
    resp = json.loads(urllib.request.urlopen(req, timeout=120).read())
    elapsed = int((time.time() - t0) * 1000)

    msg = resp["choices"][0]["message"]
    output = (msg.get("reasoning") or "") + (msg.get("content") or "")

    gt = s["ground_truth"]
    print(f"\n{'='*70}")
    print(f"样本 {i}/{N_SAMPLES}  （{elapsed}ms）")
    print(f"{'─'*70}")
    print(f"[输入]\n{s['input'][:300]}...")
    print(f"{'─'*70}")
    print(f"[Ground Truth]  violations={gt['violations']}  CPK={gt.get('cpk','?')}")
    print(f"{'─'*70}")
    print(f"[模型输出（无 Skill）]\n{output[:600]}{'...' if len(output)>600 else ''}")
print(f"\n{'='*70}")
EOF
```
