## 技能指引
---
name: line-operation-skill
description: 当用户要求全面了解某条线体的整体运营状况、综合运营情况、生产总结、运营表现、生产日报时使用此 skill。触发关键词：运营情况、生产情况、整体状态、综合表现、运营总结。仅用于 8 维度综合查询，不用于单项指标查询（单项指标请使用 line-kpi-query）。
---

## 线体运营情况综合查询

### 一、Skill 功能概述
用途：综合查询线体当日（或指定日期/班次）的运营全貌，涵盖以下 8 个维度：
1. 排产情况
2. 产出达成情况
3. 良率情况
4. 线体 OEE 情况
5. 人员出勤
6. 抛料情况
7. UPH 情况
8. 异常任务 TOP 情况

适用场景示例：
- 用户询问：总结 S03 线体今天运营情况
- 用户询问：S03线昨天生产情况怎么样
- 用户询问：P17项目S03线本班运营表现

⚠️ 不适用场景（请转用对应 skill）：
- 用户仅询问单项指标（如"S03线今天良率"）→ 使用 `line-kpi-query`
- 用户仅询问出勤情况 → 使用 `line-attendance-query`
- 用户询问工站指标 → 使用 `workstion-kpi-query`
- 用户询问项目良率 → 使用 `project-kpi-query`
- 用户询问线体，装备异常情况或异常日报 → 使用 `line-exemption-query`

---

### 二、统一执行流程（必须严格执行）
⚠️ 所有查询必须完整执行以下步骤，不得跳步或合并

**Step 1：识别查询参数**
从用户问题中解析并确认：
- 线体编码（如 S03；未指定则查全部线体）
- 项目编码（如 P17；未指定则先查询全部项目）
- 日期（未指定则默认今天）
- 班次（未指定则默认全天 ALL）

**Step 2：查找本体对象类型**
使用 `list_object_types` 搜索：
- 查询线体、项目对象类型
- 确认各对象在本体中的 apiName

**Step 3：获取对象主数据**
使用 `get_object_type_data` 查询：
- 未指定项目 → 查询全部项目编码
- 未指定线体 → 查询全部线体编码

**Step 4：获取对象指标模型 ID 和参数（关键步骤）**
使用 `get_object_type_metrics` 查询，完整记录：
- 所有指标模型 id
- 每个模型的 params（参数名、参数类型、optional 状态）
⚠️ 全部 params 不允许遗漏

**Step 5：获取系统时间**
使用 `execute_shell_command` 获取真实系统日期，用于时间参数构造。

**Step 6：前置判断——排产情况**
优先调用产出模型（12204）：
- 若返回结果中"日生产目标"为空或无数据 → **直接回答"该线体当日无排产"，终止后续查询**
- 若有排产数据 → 记录结果，继续执行 Step 7

**Step 7：依次调用剩余指标模型**
按以下顺序逐一调用（每个模型单独调用，不得合并）：
1. 产出达成（12204，Step 6 已调用，直接复用结果）
2. 良率（12198）
3. 线体 OEE（12203）
4. 人员出勤率（12385）+ 员工打卡记录（12389）
5. 抛料率（12194）
6. UPH（12202）
7. 异常任务 TOP（12223）

调用规则：
- 模型 ID 必须且只能从下方第三节映射表中选取，禁止猜测或替换
- 时间参数类型必须来自 Step 4 返回的 params 定义
- 所有 optional=false 的参数必须显式传值，禁止依赖默认值
- 构造完参数后，逐一对照 Step 4 的 params 核对，确认无缺失、无类型错误

**Step 8：Skill 调用自检（⚠️重点）**
在输出结果之前，快速检查：
- [ ] 是否完整严格按顺序执行 Step 1–7
- [ ] Step 6 排产判断是否已执行（无排产时是否已终止）
- [ ] 是否正确识别线体编码和项目编码
- [ ] 8 个维度的模型是否全部调用
- [ ] 时间参数类型是否符合映射表（date / datetime）
- [ ] 参数是否完整（对照 Step 4 的 params 逐个检查）
- [ ] 班次参数是否正确（未指定时为 ALL）
- [ ] 出勤模型 12385 和 12389 的筛选条件是否完全一致（日期、线体、班次）
- [ ] 输出是否为模型原始数据（未二次加工）

### 四、核心规则（必须遵守）

1. **规则 1：零计算、零推导、零润饰（最高优先级）**
   - 所有指标值严禁计算、推导、补算、估算、插值、回填、单位换算、同比/环比、跨模型聚合
   - 结果必须原样来自 `get_idi_model_data` 调用

2. **规则 2：今日日期唯一可信来源**
   - 必须通过 `execute_shell_command` 获取真实系统时间（Step 5 已执行）
   - 禁止依赖模型时间，禁止硬编码日期

3. **规则 3：时间范围规则（⚠️重点）**

   **3.1 识别逻辑流程（强制）**
   获取系统时间 → 计算"昨天""今天"日期 → 判断参数类型（date / datetime）
   - date 类型 → 直接用日期字符串（YYYY-MM-DD）
   - datetime 类型 → 根据班次转换为工厂时间格式
   - 用户未指定班次 → datetime 默认使用"全天"（09:00 - 次日 09:00）

   **3.2 参数类型对照表**

   | 日期类型     | 参数格式              | 示例（假设今天=2026-03-20）                                          | 说明                         |
   |--------------|-----------------------|----------------------------------------------------------------------|------------------------------|
   | **datetime** | `YYYY-MM-DD HH:MM:SS` | 全天：startTime=`2026-03-20 09:00:00`，endTime=`2026-03-21 09:00:00` | `>= startTime AND < endTime` |
   | **datetime** | `YYYY-MM-DD HH:MM:SS` | 白班：startTime=`2026-03-20 09:00:00`，endTime=`2026-03-20 21:00:00` | 当天 09:00-21:00              |
   | **datetime** | `YYYY-MM-DD HH:MM:SS` | 夜班：startTime=`2026-03-20 21:00:00`，endTime=`2026-03-21 09:00:00` | 当天 21:00-次日 09:00         |
   | **date**     | `YYYY-MM-DD`          | start_date=`2026-03-20`，end_date=`2026-03-20`                       | 生产日概念                    |

   **3.3 工厂时间基准（仅适用于 datetime 类型）**
   - 白班：09:00 - 21:00 / 夜班：21:00 - 次日 09:00 / 全天：09:00 - 次日 09:00

4. **规则 4：参数完整性检查**
   - 调用每个模型前，逐个确认 optional=false 的参数都已显式传值
   - 构造完参数后列出完整 params_json 与 Step 4 参数逐一核对

5. **规则 5：班次参数（shift）**
   - D：白班 / N：夜班 / ALL：全天
   - 模型存在 shift 参数且用户未指定班次 → 传 ALL
   - 出勤模型 12385和 12389  的 shift 必须完全一致

6. **规则 6：UPH 查询特殊规则**
   - `qt_type` 参数必须传空字符串 `""`
   - 工段 = SMT 的线体，只呈现板子类型 = "主板SMT_B" 的数据

7. **规则 7：项目与线体缺省逻辑**
   - 未指定项目 → 先查全部项目（`get_object_type_data` 查 project）
   - 未指定线体 → 查全部线体

8. **规则 8：多值参数格式**
   - 多个项目/线体：英文逗号分隔，示例：`"P3,N3,O1"`

9. **规则 9：产出数据过滤规则**
   - 工段 = SMT 的线体，只呈现制程 = "主板SMT_B" 的数据

10. **规则 10：是否出勤字段展示映射**
    - 模型返回 `0` → 展示**未出勤**；`1` → 展示**出勤**
