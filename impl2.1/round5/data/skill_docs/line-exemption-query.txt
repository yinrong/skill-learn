## 线体异常日报

### 一、Skill 功能概述
用途：无论用户如何提问，**统一输出固定格式的异常日报**，必须包含当前班次概况、与上一班次的趋势对比（今天早上9点到21点是当前班次，上一个班次应该是昨天21点到今天早上9点）、TOP 异常集中、处理人效四个部分。

适用场景示例：
- 用户询问：某天某条线的异常情况
- 用户询问：某天某项目某线体的异常数据
- 用户询问：某天某线某个班的高频异常 TOP5
- 用户询问：某天某线工站/装备的主要异常集中在哪
- 用户询问：今天/今班的异常日报

⚠️ 不适用场景（请转用对应 skill）：
- 用户询问线体综合运营情况（8维度） → 使用 `line-operation-skill`（其中已含第8维度异常TOP）
- 用户询问装备参数值/运行状态 → 使用 `equipment-parameter-skill`
- 用户询问线体单项 KPI（良率/OEE/UPH 等） → 使用 `line-kpi-query`

### 二、统一执行流程（必须严格执行）
⚠️ 所有查询，必须完整执行以下步骤，不得跳步或合并。**始终输出完整日报格式。**

**Step 1：识别本体对象**
从用户问题中解析并确认：
- 主对象：**线体**（必须）
- 附加对象（如查询工站/装备层级 TOP 异常时）：工站、装备
- 项目编码（未指定则先查询全部项目）
- 日期（未指定则默认今天）
- 班次（未指定则默认全天 ALL）

**Step 2：查找本体对象类型**
使用 `list_object_types` 搜索：
- 查询线体（以及工站/装备，如需要）的对象类型
- 确认各对象在本体中的 apiName

**Step 3：获取对象主数据**
使用 `get_object_type_data` 查询：
- 获取具体的线体编码（以及工站/装备编码，如需要）
- 用户未指定项目 → 先查询全部项目
- 用户未指定线体 → 查询全部线体

**Step 4：获取对象指标模型 ID 和参数（关键步骤）**
使用 `get_object_type_metrics` 查询，必须完整获取并记录：
- 该对象关联的所有指标模型 id
- 每个模型对应的 params：
  - 参数名
  - 参数类型（date / datetime / string 等）
  - optional 状态（true / false）
⚠️ 必须记录返回的全部 params，不允许遗漏

**Step 5：获取系统时间**
使用 `execute_shell_command` 获取真实系统日期，用于：
- 确定"今天/昨天"的具体日期
- 构造当前班次时间范围
- 推算上一班次时间范围（Step 6 使用）

**Step 6：查询当前班次数据**
按照"对象指标与模型映射关系"调用模型（严格规则）：

6.1 确定模型 ID 与时间参数类型（强制）
- 模型 ID 必须且只能通过下方第三节「对象指标与模型映射关系表」确定，禁止猜测、替换、泛化或根据经验选择
- 时间参数类型（date / datetime）必须且只能来源于 Step 4 中 `get_object_type_metrics` 返回的 params 定义
- 严禁根据模型 ID、参数名称、历史经验或上下文示例自行推断时间参数类型

6.2 时间参数类型规则
- 若时间参数类型 = "datetime" → 必须使用 datetime 类型规则
- 若时间参数类型 = "date" → 必须使用 date 类型规则

6.3 参数构造强制规则
- 所有 optional=false 的参数必须显式传值，禁止使用默认值
- 构造完成后：必须逐一对照 **Step 4** 返回的 params，确认无缺失、无类型错误

**Step 7：查询上一班次数据并判断趋势**

7.1 确定上一班次时间范围（基于 Step 5 获取的系统时间）

| 当前班次              | 上一班次 | 上一班次时间范围                          |
|-----------------------|----------|-------------------------------------------|
| 今日白班（09:00–21:00） | 昨日夜班 | 昨天 21:00:00 – 今天 09:00:00            |
| 今日夜班（21:00–次日09:00） | 今日白班 | 今天 09:00:00 – 今天 21:00:00           |
| 全天（09:00–次日09:00） | 昨天全天 | 昨天 09:00:00 – 今天 09:00:00           |

7.2 使用相同的模型 ID 和参数结构，以上一班次时间范围重新调用 `get_idi_model_data`

7.3 趋势判断规则（零计算原则：只做大小比较，不做四则运算）
- 将当前班次与上一班次的**总任务数**直接比较：
  - 当前 > 上一班：趋势 = ↑ 上升
  - 当前 < 上一班：趋势 = ↓ 下降
  - 当前 = 上一班：趋势 = → 持平
- 同理对**响应率**、**到位率**、**关闭率**进行方向判断
- **严禁计算差值、百分比变化、同比环比等任何派生数值**

**Step 8：Skill 调用自检（⚠️重点）**
在输出结果之前，快速检查：
- [ ] 是否完整严格按顺序执行 Step 1–7
- [ ] 是否正确识别了线体对象（主对象）
- [ ] 是否使用了正确的指标模型 ID（来自第三节映射表）
- [ ] 时间范围是否符合 Step 6.2 的参数类型规则
- [ ] 参数是否完整（对照 **Step 4** 返回的 params 逐个检查）
- [ ] 班次参数是否正确设置
- [ ] **Step 5 是否已获取系统时间，上一班次时间范围是否正确推断**
- [ ] **是否正确用相同模型独立查询了上一班次数据**
- [ ] **趋势判断是否仅使用大小比较，未计算差值**
- [ ] 对于工站/装备 TOP 异常查询，是否使用了对应的模型 ID（12228/12230）
- [ ] **对于 TOP 异常查询，是否严格使用模型返回的原始异常类型名称，未进行拼接、合并或修改**
- [ ] **对于 TOP 异常查询，占比数据是否直接使用模型返回的原始值，未重新计算**
- [ ] **输出是否为完整日报格式（含当前班概况 / 趋势对比 / TOP异常 / 处理人效）**

### 四、核心规则（必须遵守）

1. **规则 1：零计算、零推导、零润饰（最高优先级，强制执行）**
   - 指标（已响应任务数、平均响应时长、已关闭任务数、关闭率等）及其组成字段，严禁任何形式的计算、推导、补算、估算、插值、回填、单位换算、同比/环比、跨模型聚合或合成
   - 趋势判断唯一例外：**仅允许对两个原始值做大小比较（>/</=），输出方向符号（↑/↓/→）**，不得输出任何数值型差量
   - 结果必须仅来自合法的 `get_idi_model_data` 调用；仅允许原样使用模型返回的字段与数值进行展示（可做不改变数值的纯格式化，如百分号、千分位）

2. **规则 2：今日日期的唯一可信来源**
   - 必须通过 Step 5 的 `execute_shell_command` 获取真实系统日期
   - 禁止依赖模型自身时间，禁止主观推断或硬编码日期

3. **规则 3：时间范围规则（⚠️重点）**

   **3.1 识别逻辑流程（强制）**
   获取系统时间（Step 5）→ 计算"昨天""今天"日期 → 判断参数类型（date / datetime）
   - date 类型 → 直接用日期字符串（YYYY-MM-DD）
   - datetime 类型 → 根据班次转换为工厂时间格式
   - 用户未指定班次 → datetime 默认使用"全天"（09:00 - 次日 09:00）

   **3.2 参数类型对照表**

   | 日期类型     | 参数格式              | 示例（假设昨天=2026-03-19）                                          | 说明                         |
   |--------------|-----------------------|----------------------------------------------------------------------|------------------------------|
   | **datetime** | `YYYY-MM-DD HH:MM:SS` | 全天：startTime=`2026-03-19 09:00:00`，endTime=`2026-03-20 09:00:00` | `>= startTime AND < endTime` |
   | **datetime** | `YYYY-MM-DD HH:MM:SS` | 白班：startTime=`2026-03-19 09:00:00`，endTime=`2026-03-19 21:00:00` | 当天 09:00-21:00              |
   | **datetime** | `YYYY-MM-DD HH:MM:SS` | 夜班：startTime=`2026-03-19 21:00:00`，endTime=`2026-03-20 09:00:00` | 当天 21:00-次日 09:00         |
   | **date**     | `YYYY-MM-DD`          | start_date=`2026-03-19`，end_date=`2026-03-19`                       | 生产日概念                    |

   **3.3 工厂时间基准（仅适用于 datetime 类型）**
   - 白班：09:00 - 21:00
   - 夜班：21:00 - 次日 09:00
   - 全天：09:00 - 次日 09:00（用户未指定班次时默认使用）

4. **规则 4：参数完整性检查（⚠️重点）**
   在调用 `get_idi_model_data` 之前，必须执行以下检查：
   - 读取 **Step 4** 返回的所有 params 信息
   - 逐个确认每个 optional=false 的参数都有传值
   - 如果某个参数没有传值，即使有默认值也不允许，必须显式传递
   - 构造完参数后，列出完整的 params_json 与 **Step 4** 返回的参数进行逐一核对

5. **规则 5：班次参数（shift）**
   - D：白班 / N：夜班 / ALL：全天
   - 当模型存在 shift 参数且用户未指定班次 → 传 ALL

6. **规则 6：项目与线体缺省逻辑**
   - 用户没有指定项目 → 先查询全部项目（`get_object_type_data` 查 `project` 对象）
   - 用户没有指定线体 → 查询全部线体

7. **规则 7：多值参数格式**
   - 多个项目/线体：使用英文逗号分隔，示例：`"P3,N3,O1"`

8. **规则 8：禁止使用样例数据冒充真实结果**
