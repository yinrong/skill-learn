## 一、历史经验总结

### 1.1 Round1 关键发现（impl2.1/round1，最佳 F1=0.119）

| 发现 | 结论 |
|------|------|
| 模板数据 + 纯 SFT | F1 天花板约 0.12，输出多样性不足 |
| no-skill 曝光次数约 600 次 = 甜点 | 更多曝光不一定更好，超过后过拟合 |
| N2~N4（更多数据）反而崩溃 | 非单调 scaling：规模增大但质量不控时，模型收敛到 rule1/rule2，遗忘其余 6 条规则 |
| 提取器 bug（中文"第1条"） | 评测结果被低估，格式漂移无声掩盖真实学习 |
| 结论 | 模板数据路线走到了上界，必须换高质量教师数据 |

### 1.2 Round2 关键发现（impl2.1/round2，最佳 F1=0.430）

| 发现 | 结论 |
|------|------|
| Claude 教师数据（ws+ns 250+250）| F1 从 0.119 跳升至 0.430，超越 Claude 零样本基线 0.232 |
| ws+ns 混合 > 纯 ns | ws 数据提供完整推理链范式，提升 F1 约 0.03 |
| ns 数据 seed 质量影响显著 | v4 > v2 > v3 > v1，相同数量不同 seed 差距约 0.01~0.02 |
| 3 epoch 是甜点，5ep 灾难性过拟合 | F1 从 0.43 崩溃至 0.15，CPK 提取率跌至 43% |
| cutoff=5120 是硬性要求 | 4096 截断导致 rule8 召回=0 |
| rule2（0.448）和 rule7（0.444）持续最弱 | 与"正常"序列相似，区分边界难度高 |
| 14B > 32B（同数据规模） | 32B 在 500 条数据下无额外收益 |
| 8B 综合得分最高（0.796） | F1 较低（0.360）但推理快（28.6s）、显存少（16GB） |
| 通用能力退化率 ≈ 0（±1.2%） | 轻量 LoRA（500条, 3ep）对通用能力几乎无影响 |

## 三、提升方向（基于历史经验重新排序）

### 方向 A：弱规则专项数据（快速见效，优先执行）

**背景**：rule2/rule7 在 round2 所有实验中均最弱（0.44~0.52），且在 8B/14B/32B 上同样低，说明不是容量问题，是**数据覆盖不足**。

**执行**：
- 针对 rule2（连续 9 点同侧）生成 80~100 条边界样本：包括第 7/8/9/10 点恰好触发的边界情形
- 针对 rule7（连续 15 点在 ±1σ 内）生成 80~100 条：区分"过于稳定"vs"正常"的样本
- 与 round2 最优数据（ws+ns_v4 250+250）混合后重训

**预期收益**：rule2/rule7 召回从 0.44 → 0.60+，整体 F1 +0.02~0.04

---

### 方向 B：扩充 ns 数据池 + 多样化 ws 数据

**背景**：round2 发现 ns_v4 比 v1~v3 更优（seed 质量影响约 0.01~0.02），但只有 300 条。

**执行**：
- 扩充 ns_v4 池：300 → 600 条（相同高质量 seed 策略，更多覆盖）
- 增加 ws 数据多样性：round2 只用单一角色（SPC工程师），尝试 goal.md §2.1 的多角色数据（各角色各 50 条，共 200 条额外 ws 数据）
- 测试 ws:ns = 1:1 / 1:2 / 1:3 不同配比

**预期收益**：F1 从 0.430 → ~0.46+

---

### 方向 C：GRPO 强化训练（潜在最大增益）

**背景**：SPC 是可验证任务（规则引擎 = 确定性 reward），天然适合 GRPO。round2 SFT 已到 0.430，RL 有望突破 SFT 天花板。

**执行**（在 SFT 最优模型上接续训练）：
```
基础：expYYY-merged（14B，F1=0.430）
框架：LLaMA-Factory（finetuning_type: grpo）
奖励函数：rule_f1(pred, gt) + 0.1×cpk_accuracy + 0.05×format_bonus
每 prompt 采样：G=8
epochs：2（RL 阶段用更小 lr=5e-6）
```

**奖励设计**：
| 组件 | 权重 | 计算方式 |
|------|------|---------|
| rule_f1 | 1.0 | 规则引擎判断 violations 集合的 F1 |
| cpk 精度 | 0.1 | \|pred_cpk - gt_cpk\| < 0.1 得满分 |
| 格式合规 | 0.05 | 输出包含合法的 rule1~rule8 标识符 |

**预期收益**：F1 +0.04~0.08，可能突破 0.50

---

### 方向 D：QLoRA 量化训练（goal.md 要求）

**背景**：round1/2 全部使用 bf16 全精度 LoRA，goal.md 要求探索量化。QLoRA 可以在更少显存下训练更大模型。

**执行**：
| 实验 | 基座量化 | LoRA 精度 | 目标模型 | 预期训练显存 |
|------|---------|---------|---------|------------|
| Q1 | int4（NF4） | bf16 | Qwen3-14B | ~10GB/卡 |
| Q2 | int4（NF4） | bf16 | Qwen3-32B | ~22GB/卡 |
| Q3 | int4（NF4） | bf16 | Qwen3-72B（需下载） | ~42GB/卡 |
| Q4 | int8 | bf16 | Qwen3-14B | ~18GB/卡 |

对比同规模 bf16 LoRA 的 F1 损失，量化 F1 损失 ≤ 2% 则视为可接受。

---

### 方向 E：8 卡多 GPU 最大模型规模探索（goal.md 要求）

**背景**：8× H20（96GB）= 768GB VRAM，目前最大只跑了单卡 32B。

**执行**：
| 实验 | 训练方式 | 模型 | 卡数 | 目标 |
|------|---------|------|------|------|
| M1 | 8卡 ZeRO-3 LoRA（bf16） | Qwen3-72B | 8 | 验证可行性 + 训练时间 |
| M2 | 单卡 QLoRA（int4） | Qwen3-72B | 1 | 对比 M1 的 F1 vs 显存 |
| M3 | 4卡 ZeRO-3 LoRA | Qwen3-72B | 4 | 成本平衡点 |
| M4（可选） | 8卡 ZeRO-3 QLoRA | Qwen3-235B-A22B（MoE） | 8 | 超大 MoE 上界 |

工具：LLaMA-Factory + DeepSpeed ZeRO-3。

---

### 方向 F：替代训练框架（goal.md 要求）

**背景**：round1/2 只用了 LLaMA-Factory，goal.md 要求探索不同框架。

| 框架 | 特点 | 验证实验 |
|------|------|---------|
| **Unsloth** | 2x 训练速度，更少显存，内置 QLoRA | 用 Qwen3-14B 对比 LLaMA-Factory，固定数据，比较 F1 和训练时间 |
| **trl（HuggingFace）** | 官方 GRPO/DPO/SFT 实现，与 PEFT 原生集成 | GRPO 方向 C 的备选框架 |

**验证标准**：F1 差异 < 1%，训练时间或显存有改善则推荐切换。

---

### 方向 G：MoE 架构对比（Qwen3-30B-A3B）

**背景**：30B 总参但每次推理只激活 3B，推理显存 ≈ 20GB（接近 14B），但参数容量远大于 14B。

**执行**：用 round2 最优数据（ws+ns_v4 250+250）训练 Qwen3-30B-A3B，与 expYYY（14B）直接对比。

**下载**：`modelscope download --model Qwen/Qwen3-30B-A3B --local_dir /home/yinrong/models/Qwen3-30B-A3B`

**预期**：若 F1 ≥ 0.45 且推理时间 ≤ 50s，则 MoE 性价比优于 14B。

## 五、Go/No-Go 标准

| 实验 | 通过标准 | 失败处理 |
|------|---------|---------|
| R3-A（弱规则） | rule2/rule7 召回 ≥ 0.60 | 增加边界样本数，改变 seed 策略 |

| R3-G（MoE） | F1 ≥ 0.45 且推理时间 ≤ 50s | 记录为负向结果，仍有参考价值 |

**进入 round4 条件**：任意方向达到 F1 ≥ 0.50，或所有 goal.md 维度均有实测数据。
